# Benchmark 决策可靠性指标

2026-09-23，报告 `format_version: 3` 包含 v2 的决策可靠性指标，并增加 C++ 路线应用结果与剩余路线重叠率。每次运行的字段位于 `runs[]`，按场景与策略分组后的均值、P50、P95、最小与最大值位于 `aggregates[]`；JSON 与 CSV 使用相同字段名。

| 字段 | 含义 |
| --- | --- |
| `guard_rejections` | 本地 Guard 拒绝策略建议的次数。包括候选无效、版本失配、收益不足和冷却限制；这些建议会被替换为保持路线。 |
| `action_attempts` | 向环境提交动作的次数，包括首次动作及失败后的保持路线降级请求。 |
| `action_rejections` | 提交获得 HTTP 4xx，或成功 HTTP 响应内 `accepted: false` 的次数。降级请求自身被拒绝也计入。 |
| `action_failures` | 提交获得非 4xx 的环境错误响应次数，通常为 HTTP 5xx。它与明确拒绝分开计数。 |
| `fallbacks` | 原动作提交失败后，保持路线的降级请求获得 `accepted: true` 的次数。模型失败转规则策略仍使用原有 `model_failures`。 |
| `route_change_requests` | 获准提交的候选道路序列与当前观察中的剩余道路序列不同的次数。 |
| `unchanged_route_requests` | 获准提交的候选道路序列与当前剩余道路序列完全相同的次数，与算法名称或候选编号无关。 |
| `native_route_applications` | C++ 已成功应用的路线次数，包含同路应用。 |
| `native_route_failures` | C++ 在应用边界因封路等原因无法应用路线的次数。 |
| `applied_route_changes` | 成功应用后，剩余道路序列或端点偏移实际改变的次数。 |
| `applied_unchanged_routes` | 成功应用后，剩余道路序列和端点偏移均未改变的次数。 |
| `route_overlap_ratio` | 本 Episode 成功应用记录的新旧剩余路线覆盖长度重叠率的均值，取值 0–1；没有成功应用时为 `null`。 |

提交指标仅在两侧道路序列均非空时比较，使用同一决策边界的观察，不把正常行驶消耗的道路前缀误算成改道。两项计数之和可能小于 `replanning_count`，差额是无法比较路径的获准提交。它们不证明路线在下一 tick 成功应用；提交与应用之间仍可能发生封路。

执行指标使用 `playback.route_comparison_version: 1` 下的 `reroutes` 原生记录。C++ 在替换路线之前保存旧路线索引和车辆双精度偏移，导出时比较旧路线的剩余部分与新路线；逐 tick 推进不计算重叠率。成功记录包含 `route_changed` 与 `remaining_overlap_ratio`，失败或缺失边界的记录对应两字段为 `null`。Python 只聚合当前 Agent 车辆的记录。

重叠率 = 新旧有向道路覆盖区间的交集长度 / 并集长度。首末道路按真实偏移裁剪，重复经过同一有向道路的重叠区间只计一次，反向道路分别计算；边集合相同而顺序不同仍算路线变化。相同且长度为零的剩余路线定义为 1，其余零并集为 0。该指标衡量路线覆盖变化幅度，不等于 A→B→A 抖动频次，也不代表较高重叠一定更优。

跨 Episode 的 `route_overlap_ratio` 对每次运行的均值再做等权统计，不按应用次数加权。无成功应用的运行不提供重叠率样本；有成功应用但部分比较记录缺失时，保留成功/失败计数，将变化计数和重叠率留为 `null`，避免不完整证据造成偏差。旧 Worker 没有比较版本标记时，全部新增执行指标留空。

可靠性指标对所有有计数证据的 Episode 聚合，包含失败的运行。未产生完整 EpisodeTrace 的异常（例如连接中断）将新增字段写为 `null`，不伪造零值，也不参与这些指标的均值。原生指标需要成功获取 Environment 结果；未结束或结果获取失败时留空。旅行时间等原有指标仍只聚合成功运行。v1/v2 历史报告不迁移、不补零；Web 显示 `—`，仍支持原样导出。

计数保存在 LangGraph 状态与 EpisodeTrace 中，支持 SQLite 节点中断后恢复；已完成的 act 节点不会重复计数。HTTP 200 但明确拒绝的回执不会记为成功提交；降级再次拒绝时停止 Episode。

验收覆盖普通循环和 LangGraph、HTTP 409/503、否定回执、降级拒绝、Guard 替换、路径比较、跨检查点恢复、失败运行聚合、JSON/CSV 与任务数据库持久化。

真实地图验收：武汉 `map_71ad2c3c46bb59ae`，起点 `(114.4911555, 30.9567005)`、终点 `(114.4565038, 30.9259153)`，第 1 秒关闭道路 `233355`。动态 A* 与规则 Agent 均于第 723 tick 到达，各记录 13 次动作提交尝试、1 次变更路线提交、0 次拒绝与降级。通过真实任务服务落库报告和浏览器图表、逐次详情核对；Python 全量 124 项测试与前端生产构建通过。

v3 验收：同一武汉场景两种策略均记录 1 次路线应用成功、1 次实际改道、0 次应用失败，重叠率为 `0.771840`。浏览器显示 77.2%，旧 v2 报告对应指标显示 `—`。C++ 回归覆盖封路导致应用失败、消费前缀后的同路应用、首末偏移裁剪、重复覆盖合并、反向道路、零长度及缺失边界；`make test`（含 Python 138 项）、前端构建和包含重启恢复的 `make algorithm-e2e` 通过。

## v4：自定义代码与种子随机事件

`custom_code` 策略要求 `source`（非空，UTF-8 最多 32 KiB），可设 `steps`（1000–5000000，默认 5000000）。在初始暂停边界执行代码，之后在事件边界重复。`ctx.keep()` 提交保持路线；合法候选提交后推进一帧，确认车辆采用才标记 `applied`。执行错误、无路、候选过期、动作拒绝或采用失败均停止本次运行，不自动降级。取消在代码返回后、提交之前检查；已确认提交的动作先完成一次推进。每次运行使用独立会话，结束后释放。

新增报告字段：`source_revision` 为源码 SHA-256（非代码策略为空），`scenario_revision` 为规范化场景配置 SHA-256，`resolved_road_controls` 保存本轮完整道路事件，`custom_decisions` 保存代码结果、日志、错误行、候选与执行状态。报告 manifest 保留完整源码。CSV 中事件与记录使用 JSON 字符串编码。v1–v3 报告继续原样读取，新字段缺失显示空值。

场景 `randomEvents` 示例：

```json
{"edgeIds":[7,8,9],"count":2,"startSeconds":30,"endSeconds":300,"durationSeconds":60,"action":"close","value":0.5}
```

使用私有伪随机数生成器，种子为 `seed + repetition - 1`。先对道路池去重排序，再无放回选择道路与发生 tick。同轮所有策略共享相同事件；重复轮次变更种子。发生窗口向内对齐到 tick，持续时间向上取整为完整 tick，事件按时间排序；结束时封路恢复开放，降速恢复为 1。不得与手动控制的道路重叠，最晚结束时间不得超过仿真时限，窗口必须至少包含一个 tick。没有随机事件时仍保留原 seed 语义。实际事件表是复现依据，不能只依赖种子跨运行环境复现。

回归覆盖代码执行、保持路线、拒绝与失败、取消、不采用路线、源码字节限制、同轮跨策略事件一致、重复轮次变化、tick 对齐、事件恢复及 JSON/CSV 证据保留。`make algorithm-e2e` 另用真实 Go/Python/C++ 验证代码评测到达与原生改道指标。

## v5：路线回切（A→B→A）

报告新增 `route_reversals`，记录车辆实际采用路线后，又回到前一次放弃路线的次数；按 Episode 聚合均值、P50/P95、最小值和最大值，JSON/CSV 与报告界面使用同一口径。它是路线稳定性的观察指标，没有时间窗口，也不判断回切是否合理；例如道路重新开放后回到原路线同样会计入。

依据 C++ 导出的 `playback.route_reversal_version: 1` 和每条原生应用记录的 `route_reversed`，不使用算法名、候选 ID 或提交次数推断。按每辆车的应用顺序比较最近两次不同路线选择：A→B→A 计一次，A→B→A→B 计两次，A→B→C→A 不计；同路重提交和失败动作不打断序列，不同车辆各自统计。

比较保留道路顺序和精确终点偏移。车辆在两次选择之间已驶过的道路必须与原路线 A 的前缀一致，再比较当前剩余路线；在相同道路上前进不会漏计，驶过不同分支后重新遇到相同道路也不会误计。重复道路按实际路段索引推进，不搜索首个同名道路。比较与重叠率一样，仅在导出结果时进行，不增加逐 tick 的路径比较开销。

失败动作的 `route_reversed` 为 `null`，不参与计数。成功动作缺失应用边界、路线连续性中断或时间倒序时，回切证据为 `null`；该 Episode 的计数也留空，避免把不完整记录当成零。完整原生记录且没有回切（包括没有任何路线应用）时为 0。旧 Worker 没有版本标记、或旧报告没有该字段时显示 `—`，不补零，原有改道与重叠指标仍可使用。

回归覆盖 A→B→A→B、同路应用、失败动作、多车辆交错、跨道路前进、重复道路、终点偏移、零长度路径、记录缺失与时间倒序，以及失败 Episode 聚合和 JSON/CSV 缺失值。端到端验收额外执行 A→B→快照恢复→A，验证恢复仍保留原生回切证据。

v5 验收：`make test` 全量通过（Python 174 项、前端导航 11 项、C++ 与 Go），前端生产构建通过。临时路网和武汉真实地图均通过 `make algorithm-e2e`：原有代码导航及后台重启恢复仍在预期 tick 到达，自定义代码评测无误报回切，专门构造的 A→B→快照恢复→A 恰好导出一次回切。
