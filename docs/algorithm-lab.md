# 自定义导航算法实验台

工作台顶部的 **CODE** 打开地图旁的代码控制台。用户编写 `route(ctx)`，选择起终点后点击运行，系统创建只读快照、执行算法、独立验证路线，并在地图展示路线和搜索回放。草稿保存在当前浏览器；完成的实验保存到服务器，可在“实验历史”恢复和对比。

顶部 CODE 用于静态旅行时间和临时封路实验。AGENT 决策控制台的“代码”页则连接车辆会话，使用当前封路与拥堵代价，生成可提交的精确路径；两处共享 `route(ctx)` 和浏览器代码草稿。路由代价不预测未来信号等待，实际仿真仍按交通与信号规则执行。

## 从代码到车辆执行

### 连续自主导航

创建 AGENT 任务后，在“代码”页点击 **开启自动导航**。第一次决策在当前暂停边界执行（包括出发前的 tick 0），之后根据封路或周期事件调用同一份代码。循环严格串行：读取观察 → 运行 Python → 验证候选 → 提交动作 → 推进一帧并确认执行 → 等待下一事件。已到达的车辆停止循环；没有可行初始路线的车辆暂不能启动。

- **单次决策**：立即在当前边界执行一次代码，提交并推进一帧后暂停。
- **暂停 / 继续**：保留车辆会话和记录。暂停会阻止下一次请求，已发出的请求会完成；推进事件时每次最多 16 帧，再检查暂停。若在提交中暂停，动作可能已入队，下一次推进才会应用，记录显示“已入队，尚未推进”。
- **停止**：退出自动循环，车辆会话仍保留，之后可以手动操作或重新开启。
- **错误处理**：代码错误、预算耗尽、无路可达、版本冲突或提交后没有成功采用路径，都会停止循环并显示错误。自动循环不替用户选择另一条路线。决策屏障保留原有墙钟超时（默认 5 分钟）；超时只确认保持路线，不自动推进时间。
- **生命周期**：自动循环由打开的 Agent 页面驱动。切换离开页面、关闭页面或修改源码会阻止后续自动步骤；服务端让已经发出的原生请求完成，浏览器断开不会因此终止共享地图进程。服务端命令超时和进程故障仍可能使会话失效。需要关闭页面后继续运行时，使用下述独立的后台导航任务。刷新后可从导航历史手动恢复到已保存边界，恢复不会自动推进。
- **决策记录**：记录完整源码、观察、状态版本、代码/快照哈希、道路序列、日志、错误行和执行状态。每次开始自动导航或单次决策都会建立独立导航历史，本次最多记录 200 条，达到上限暂停；页面显示最近 10 条，可导出全部 JSON。记录中的阶段是该次循环最后确认的状态，暂停后进行的手动操作不会回写旧记录。源码、记录与原生车辆快照在服务器一起持久化，刷新后可查看并手动恢复。

`ctx.observation()` 返回独立副本，修改它不会改变车辆或快照。静态模式仅返回 `{"mode":"static"}`；车辆模式还包含 `tick`、`stateVersion`、`simulationTimeS`、`decisionReason` 和 `vehicle`。车辆字段包括 `vehicleId`、`state`、`routeId`、`position`（行驶时为 `edgeId/offsetM`，等待出发时为 `None`）、`destinationEdgeId`、`destinationOffsetM`、`remainingEtaS`、`routeInvalidated`、`held`、`remainingEdgeIds`。封路等情况使剩余 ETA 不可计算时，`remainingEtaS` 与普通观察接口一致返回 0；是否需要重规划应检查 `routeInvalidated`，不能把该 0 当作已经到达。剩余道路最多返回 10,000 项，是否截断由 `remainingEdgesTruncated` 表示。复制观察也消耗解释执行及容器预算。

例如明确保持当前路线，同时留下决策原因：

```python
def route(ctx):
    observation = ctx.observation()
    ctx.log(observation["decisionReason"])
    return ctx.keep()
```

`return ctx.keep()` 仅适用于车辆模式，结果为 `phase: "kept"`，自动循环提交 `keep_route`；手动运行则显示“提交保持路线”按钮。它与 `return None` 不同，后者仍表示无路可达。可以先检查 `observation["vehicle"]["routeInvalidated"]`，决定保持路线或执行自定义搜索。

新增 `POST /api/maps/{id}/agent/sessions/{session}/decisions`，请求为 `{"vehicleId":0,"basedOnStateVersion":1}`，在当前暂停边界创建或返回已有的决策 ID。`GET` 会话观察同时返回当前 `decisionId`。`POST /step` 可携带 `basedOnStateVersion`，重复或过期推进会返回 409；同一会话的写操作互斥，避免自动导航和手动操作交错推进。

### 后台导航任务

2026-09-24：AGENT 代码页提供“交给后台运行”。任务冻结启动时的源码，在服务端按观察、执行代码、提交、推进与检查点保存的顺序运行；关闭或刷新浏览器不会停止任务，编辑浏览器草稿也不会改变已启动任务的源码。

- 暂停、停止在当前决策及保存完成后的边界生效。每次普通推进最多 16 tick；一次代码决策最多受既有 30 秒请求预算约束。
- 暂停保留独占会话，可继续；停止、完成或错误退出后释放独占。独占期间仍可观察，但手动推进、提交、快照、删除会话均返回 409。
- 服务正常关闭时暂停任务；异常中断后，磁盘中的运行状态按暂停加载。用户点击“继续 / 恢复”后才按原生检查点创建新会话，不自动恢复执行。
- 首次推进前及每个确认边界保存检查点；保存失败立即停止，展示的已保存 tick 不前移。失败记录保留源码版本、观察、日志与错误行；已提交但未确认执行的动作仍标为 `queued`。
- 车辆真正到达才标为完成，仿真时限结束但未到达会报错。每个任务最多 200 次决策，达到上限暂停；停止后可从当前车辆创建新任务。
- 每张地图最多 100 个任务，每个持久化文件最多 16 MiB，位于 `data/maps/{id}/navigation-jobs/`。运行或暂停中的任务必须停止后才能删除；导出包含源码、记录及最近原生检查点。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/maps/{id}/agent/sessions/{session}/navigation-jobs` | `{source, vehicleId}` 启动后台任务，返回 202 |
| GET | `/api/maps/{id}/agent/navigation-jobs` | 列出任务摘要 |
| GET / DELETE | `/api/maps/{id}/agent/navigation-jobs/{job}` | 获取完整记录或删除已退出任务 |
| POST | `/api/maps/{id}/agent/navigation-jobs/{job}` | `{action: "pause" / "resume" / "stop"}` 控制任务 |

会话观察中的 `navigationJobId` 表示当前独占任务。浏览器可连接现存会话查看进度；服务重启后先恢复任务，再连接新的会话。

### 导航历史与恢复

自动导航在首次动作之前、每次已确认动作之后，以及暂停、完成或失败退出时保存检查点。只有服务器成功保存后才继续下一步；保存失败、容量不足或版本冲突都会暂停，保留上一份成功的历史。车辆已执行但保存失败时，当前页面仍保留真实的执行记录，用户可以导出。

“导航历史”按地图列出最近保存边界，支持查看源码、决策记录、导出、删除和“恢复代码与车辆”。恢复使用同一份历史版本，新建独立的暂停会话；恢复成功后关闭当前页面原先操作的会话，再由用户决定继续。再次开始会创建新的历史，不覆盖原历史。正在其他页面更新的历史必须刷新到最新版本后才能恢复。

刷新或关闭页面可能中断尚未保存的请求。恢复只保证回到明确显示的已保存 tick，不声称包含原会话后来执行的动作。页面上的“清空”只清理本次显示记录，不删除服务器历史；删除历史不会关闭正在运行的会话。

每张地图最多 100 次导航历史，单次最多 200 条记录，源码上限 32 KiB，包含车辆快照的文件上限 16 MiB。文件保存在 `data/maps/{id}/navigation-history/nav_*.json`，通过原子替换将源码、记录和 C++ 动作快照保存为同一个文件；临时原生快照随即释放。决策记录由 Web 循环报告，仅作审计展示，恢复只使用服务端生成的原生快照，客户端不能提交替代的车辆动作日志。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/api/maps/{id}/agent/sessions/{session}/navigation-history` | 保存当前暂停/完成边界；传 `id`（首次省略）、`revision`（首次为 0）、`basedOnStateVersion`、`source`、`records` |
| GET | `/api/maps/{id}/agent/navigation-history` | 查询摘要，按最后更新时间倒序 |
| GET / DELETE | `/api/maps/{id}/agent/navigation-history/{history}` | 读取完整历史或删除 |
| POST | `/api/maps/{id}/agent/navigation-history/{history}/restore` | 携带 `revision` 恢复为新的暂停会话 |

历史写入以 `revision` 校验并发覆盖；快照以原生 `stateVersion` 校验暂停边界。旧版本、跨会话更新或容量已满返回 409，文件超过上限返回 413。无论保存成功与否，都不会隐式推进仿真。

### 手动生成与提交

1. 进入 **AGENT**，点选起终点，启动任务并点击 **推进至事件**。
2. 在右侧 **代码** 页编写 `route(ctx)`，点击 **生成候选**。系统冻结在当前决策边界，从车辆当前位置及原目的地生成只读路网快照。`neighbors` 的费用含当前拥堵与转向代价，封闭道路和禁转已过滤。
3. 查看地图路径与计算结果，通过地图上的 **提交所选候选** 确认采用，或选择 **保持路线**。生成候选本身不改变车辆路线。
4. 推进仿真。车辆按提交的道路序列行驶，即使它比 Dijkstra 绕远也保留用户选择。行驶中的车辆不能通过改写起点跳到反向或相邻道路，终点也不能改变。

提交需要暂停且版本匹配，并重新检查路径合法性。下一 tick 的封路等控制先执行，路径随后再校验；如果此时已不合法，保留原路线并记录失败的 reroute，不自动换成另一条规划结果。提交返回 `appliesAtNextTick` 表示已入队，最终是否换路以推进后的观察和仿真结果为准。

车辆代码使用相同 Python 解释器、5 秒计算/10 秒子进程/30 秒请求、1 GiB 内存和全局两个执行名额；界面预算为 500 万步。修改源码会取消运行并撤下旧的自定义候选。当前车辆模式只支持普通运行；单步调试仍在静态 CODE 实验台使用。车辆代码运行结果不写入静态实验历史，已提交的完整路径会写入 Agent 快照动作记录，格式版本为 3；读取仍兼容版本 1/2。恢复精确路径时保留双精度偏移，重新检查路径，不按算法名称重算替代路线。

接口：`POST /api/maps/{id}/agent/sessions/{session}/algorithms/plan`

```json
{"vehicleId":0,"basedOnStateVersion":32,"source":"def route(ctx):\n    return None","steps":2000000}
```

成功返回 `{ "result": ..., "candidate": ... }`，其中 `candidate.algorithm` 为 `custom`，含 `candidateId`、`basedOnStateVersion`、`edges`、`timeS`、`lengthM`；`result.geojson` 是 C++ 按起终点偏移裁切的候选几何，地图直接使用它。执行失败或确认无路时只有 `result`，不产生候选。起终点与封路条件取自服务器会话，请求不能覆盖；每个边界最多保留 128 个候选，自定义规划会清理旧边界候选。

将候选交给现有 `/actions` 接口，携带该决策的 `decisionId`、`vehicleId`、`basedOnStateVersion` 和 `kind: "commit_route"`。旧候选不能用新版本号重新包装提交。静态实验生成的路线也不能直接作为车辆候选，必须在车辆快照上重新运行代码。

## 单步与断点调试

在同一份代码、起终点及封路条件下点击 **调试**，进程会停在第一条可执行语句之前。黄色行标记下一条语句，变量面板展示当前函数的局部变量、调用栈、执行步数和日志。

- **单步**：执行到下一条语句前；调用辅助函数时会进入函数，函数返回后回到调用方。
- **继续到断点**：在“实验条件与执行限制”填写断点行号，例如 `8,23`。继续执行会在这些语句前暂停；清空断点则运行到结束。循环条件断点每次迭代都会检查。空行、注释和顶层函数声明不触发断点。
- **停止**：取消并终止整个进程。关闭实验台、切换地图或修改代码、起终点、封路、预算也会停止调试。修改断点可以保留现场，下一条命令采用新断点。
- **变量预览**：当前函数最多 24 个变量，容器最多展开两层、每层前 6 项；字符串、长变量名和大容器会截断。循环引用不会无限展开，路网对象只显示 API 标签，不开放内部属性。

暂停保留的是同一个 Python 解释器进程的现场。暂停等待不计入 5 秒解释执行时间；每次继续后的执行最多等待 10 秒，完成后的 C++ 校验最多 20 秒。每个会话最长 10 分钟，暂停 60 秒未发送调试命令即结束，最多暂停 1000 次、设置 64 个断点。暂停中的会话仍占用两个全局执行名额之一，并受内存监控。服务关闭会回收全部调试进程。

调试命令携带上一次暂停的 `sequence`。重复或迟到的命令返回 409，不多执行一步；同一会话的并发命令也会拒绝。最终路线使用与普通运行相同的 C++ 校验与实验保存流程。历史结果用 `executionMode` 区分运行和调试，调试的计算耗时包含额外检查开销。

当前不支持条件断点、单步跳过函数、反向执行、修改现场变量、对暂停会话断线重连，或在任意表达式中途暂停；需要提前设置断点，执行期间可以停止整个进程。历史实验只保存完成后的结果，不保存可恢复的暂停进程。

## 控制边界

| 用户控制 | 平台控制 |
| --- | --- |
| 搜索顺序、剪枝、启发式、优先队列评分和自己的变量 | 道路方向、禁转、转向代价、起终点吸附和合法后继 |
| 地图点选或精确输入 WGS84 起终点 | 吸附半径 100 米，匹配失败直接报告 |
| 最多 256 条临时封闭有向道路索引 | 同一封路条件同时应用于自定义算法和 Dijkstra 基准 |
| 运行、停止和步数预算 | 进程生命周期、内存、时间、输出与并发限制 |
| 搜索记录及日志 | 路径逐步校验、最终时间和长度重新计算 |

代码可以按 `length_m` 搜索最短距离，也可以按 `cost` 搜索最短时间；验证结果中的旅行时间始终由平台计算。与 Dijkstra 的百分比比较以旅行时间为准，合法路线不必是时间最优路线。

## 方法契约：zeus-routing-v1

入口必须是 `def route(ctx)`。普通状态表示“沿某条道路到达末端路口，以及此前触发的转向历史”。状态 ID 不透明，必须通过后继查询获得；`neighbors` 中的 `edge` 才是物理道路索引。没有 via-way 时两者一致，有 via-way 时同一道路可能对应多个状态，以区分不同历史并检查序列限制。道路索引只在所属地图版本内有效。

| 方法 | 返回值与语义 |
| --- | --- |
| `ctx.observation()` | 只读观察的独立副本；具体字段见连续导航说明。 |
| `ctx.keep()` | 仅车辆模式，作为返回值明确保持当前路线；不生成替代候选。 |
| `ctx.start()` | 虚拟起点 `-1` |
| `ctx.goal()` | 虚拟终点 `-2` |
| `ctx.neighbors(state)` | 合法后继字典列表：`state` 下一状态、`edge` 本次经过的有向道路、`cost` 秒、`length_m` 米。包含起终点所在道路的部分长度与转向罚时；返回副本，修改它不会改变快照。终点返回空列表。 |
| `ctx.estimate(state)` | 到吸附终点的直线距离除以全图最高速度，单位秒；本版本静态条件下可用于 A* 的可采纳启发式。虚拟状态返回 0。 |
| `ctx.queue()` | 最小优先队列；`push(state, priority)`、`pop()` 返回 `(state, priority)`、`empty()`。同分按插入顺序弹出，空队列 `pop` 报错。 |
| `ctx.record(state, g, f)` | 记录当前状态末端路口的搜索事件。虚拟状态不记录；重复状态允许。`g/f` 是算法报告值，仅用于回放。 |
| `ctx.route(states)` | 构造返回值。完整路径必须从 `start` 到 `goal`，包括两端虚拟状态；最多 10,000 项。随后 C++ 检查每次转移是否合法。 |
| `ctx.log(value)` | 输出标量（字符串、数字、布尔或 `None`）；超过日志上限的记录忽略。 |

无路可达时 `return None`。平台会核对 Dijkstra：如果基准能找到路线，自定义算法的无路结论会验证失败。用户代码不能获取基准路径。

编辑器内附 Dijkstra 模板。下面是使用相同方法的 A* 示例：

```python
def route(ctx):
    frontier = ctx.queue()
    frontier.push(ctx.start(), 0)
    best = {ctx.start(): 0}
    parent = {}
    while not frontier.empty():
        state, priority = frontier.pop()
        cost = best[state]
        if priority != cost + ctx.estimate(state):
            continue
        ctx.record(state, cost, priority)
        if state == ctx.goal():
            path = [state]
            while state != ctx.start():
                state = parent[state]
                path.append(state)
            path.reverse()
            return ctx.route(path)
        for step in ctx.neighbors(state):
            next_state = step["state"]
            next_cost = cost + step["cost"]
            if next_cost < best.get(next_state, 1e15):
                best[next_state] = next_cost
                parent[next_state] = state
                frontier.push(next_state, next_cost + ctx.estimate(next_state))
    return None
```

## 语法和执行限制

运行器用自定义 AST 解释器逐步解释 Python 子集，不对用户源码调用 `exec` 或 `eval`。支持普通函数、条件、循环、列表、字典、元组、解包、索引、算术和比较。内置 `len`、`range`、`abs`、多数字参数的 `min/max`；列表有 `append/reverse`，字典有 `get`。不支持导入、文件、网络、类、反射、推导式、第三方包、关键字参数、函数默认参数或类型注解。

编辑器使用按需加载的 CodeMirror，提供 Python 高亮、行号、撤销/重做、Tab 缩进、括号匹配、`ctx.` 方法补全、错误定位和 Cmd/Ctrl+Enter 运行。停止输入 700 ms 后发送源码检查请求，只检查语法、入口及已知禁止的调用，不执行代码或读取地图；类型、变量和路线错误仍在运行时判断。语法检查使用相同的解释器规则，进程限时 2 秒，复用服务并发门禁；繁忙时提示检查暂不可用。

| 资源 | 上限 |
| --- | --- |
| 源码 | UTF-8 32 KiB |
| 解释执行时间 | 5 秒，在解释器计数点检查 |
| 子进程总墙钟时间 | 10 秒，包含 Python 启动、快照读取及输出；父进程超时强制终止 |
| 请求总时间 | 30 秒，包含 C++ 创建快照和校验 |
| 子进程 CPU / 内存 | 8 秒 CPU；Linux 地址空间 1 GiB，macOS 父进程每 50 ms 采样 RSS，超过 1 GiB 或无法监控时终止 |
| 解释步数 | 默认 2,000,000；API 1,000–5,000,000，界面提供三档 |
| 后继查询 | 100,000 次 |
| 容器 | 每个最多 200,000 项；累计分配计数 2,000,000 |
| 函数 | 最多 16 个，调用深度最多 16 |
| 数字 / 字符串 | 有限数、绝对值 ≤ 10¹⁵；单字符串最多 4096 字符 |
| 日志 / 搜索回放 | 前 100 条日志，每条 1000 字符；前 5000 个搜索事件 |
| 地图快照 | 500,000 条有向道路、2,000,000 次转移、128 MiB |
| 服务并发 | 最多 2 个请求，超额返回 429 |

步数计算包含语句、表达式、循环及后继查询，不等于道路数量。大地图长距离 Dijkstra 可能达到预算；可缩短起终点距离、选择扩展预算或改进搜索策略。macOS RSS 是采样限制，瞬时内存可能超过阈值。解释器耗时不包括快照创建，不宜直接与原生 C++ 算法耗时比较。

停止按钮中断 HTTP 请求，Go 取消上下文并终止对应子进程。每个请求有独立临时目录，结束后清理。代码只接触明确白名单方法；Python 启动使用隔离模式，环境仅保留 PATH 和 LANG。执行器是应用内语言边界，当前面向本地工作台；公开多租户部署还需要独立的系统级容器隔离与认证。

## 结果和版本

结果包含代码 SHA-256、快照 SHA-256、原生 Dijkstra 指标、用户算法耗时、查询次数和可选搜索轨迹。快照哈希来自包含转移、代价、启发式、路口映射和基准指标的规范化 JSON，不是历史快照下载标识。

每次完成的执行自动保存为 `data/maps/{id}/algorithm-experiments/run_*.json`，包含请求源码、起终点、封路、步数预算以及完整结果、路线和回放轨迹。文件通过原子替换写入，服务重启后可读取。每张地图最多 100 次；达到上限仍返回本次计算结果，但明确提示未保存，不自动删除历史。用户可删除记录释放容量。请求取消、参数错误或快照创建失败不保存。

“恢复代码与结果”会恢复对应源码、条件与历史结果，再次点击运行可重新验证。勾选两次已验证且 `snapshotId` 相同的实验，展示旅行时间、长度、后继查询次数和解释执行耗时对比；不同条件不会显示可比结论。历史恢复是已保存结果的回放，底层路网快照文件本身没有长期保存。

修改源码、起终点、封路或预算后，上一结果标记过期，地图隐藏旧路线及轨迹。运行中修改输入不会把旧结果当作新结果。关闭控制台或切换地图会取消活动请求。

## API 与运行环境

- `GET /api/algorithms/capabilities`：方法契约、语法、限制和模板。
- `POST /api/algorithms/check`：`{ "source": "..." }`，返回 `ok` 与可选的 `error/line`。
- `POST /api/maps/{id}/algorithms/run`：JSON 字段 `fromLon`、`fromLat`、`toLon`、`toLat`、`source`，可选 `closedEdges`、`steps`。
- `POST /api/maps/{id}/algorithms/debug`：同运行请求，返回首个暂停事件或最终结果。暂停事件包含 `sessionId`、`kind: "paused"`、`sequence`、`line`、`variables`、`frames`、`steps` 等。
- `POST /api/maps/{id}/algorithms/debug/{sessionId}`：`{ "action": "step" 或 "continue", "sequence": 上次暂停序号, "breakpoints": [8,23] }`。返回下一暂停事件，或 `kind: "finished"` 与嵌套 `result`。
- `DELETE /api/maps/{id}/algorithms/debug/{sessionId}`：终止调试；不存在或过期的会话返回 404。
- `GET /api/maps/{id}/algorithms/experiments`：实验摘要列表，按时间倒序。
- `GET /api/maps/{id}/algorithms/experiments/{run}`：恢复完整请求与结果。
- `DELETE /api/maps/{id}/algorithms/experiments/{run}`：删除一条实验。
- 成功调用返回 `ok`、`phase`、`error/line`（若有）、`codeRevision`、`snapshotId`、`baseline`、`steps`、`expandedNodes`、`computeMs`、`logs`、`searchTrace`。通过校验后另有 `geojson`、`timeS`、`lengthM`、`edges`。
- `phase` 为 `execution`、`validation`、`verified` 或 `unreachable`。HTTP 200 也可能是 `ok:false`；无效请求 400、地图不存在 404、快照错误 422、并发超限 429。
- 已保存的运行包含 `runId`；保存失败包含 `storageError`，不覆盖本次算法的验证结论。

控制服务需可运行 Python 3.9+（Linux/macOS），默认 `python3`，可用 `--algorithm-python /absolute/path/to/python3` 指定。不依赖 Agent Runtime 的第三方 Python 包。`make run` 仍是统一启动入口。

测试覆盖 C++ 部分道路端点、转向罚时/禁转/封路和非法跳跃校验，Python 主机访问拒绝、容器隔离、无限循环、递归、日志及轨迹上限，以及 Go 子进程取消和输出限制。

## 端到端验收

```bash
make algorithm-e2e
```

该入口构建 C++ 和 Go，用临时路网启动独立控制服务，并直接调用 Web 使用的 `runAlgorithmNavigation`。覆盖静态 Dijkstra 对照、封路绕行、调试单步与重复命令拒绝、服务重启后的源码/结果恢复、车辆精确路径与偏移恢复，以及封路触发自定义代码重规划并最终到达。每次运行创建独立数据目录与端口，退出后回收服务和临时文件；同时验证后台导航暂停、重启恢复和自定义 Benchmark 的真实 Python 客户端；需要 `uv` 与 Agent Runtime 依赖，不需要模型供应商。

已有真实地图可以使用同一验收脚本（先完成构建）：

```bash
node --experimental-strip-types scripts/algorithm-e2e.mjs \
  --map data/maps/map_71ad2c3c46bb59ae \
  --origin 114.4911555,30.9567005 \
  --destination 114.4565038,30.9259153 \
  --closed-edge 233355
```

`--map` 为包含 `map.zmap` 与 `record.json` 的目录。脚本将其复制到临时目录，不修改原地图、快照和历史。起终点应形成至少三条道路的路线，且中间道路封闭后仍可绕行。默认封闭路线中间的道路，可通过 `--closed-edge` 指定路线内部另一条道路；道路索引依赖地图版本。预算不足或没有替代路径会明确验收失败。该检查验证实际跨语言控制链路，浏览器布局与鼠标交互仍需另行验收。

### 快照完整性与地图绑定

新快照（格式 3）包含规范化 JSON 的 SHA-256、原始 `map.zmap` 内容哈希与重放契约版本。恢复前验证内容、契约及当前地图文件，错误发生时不创建或推进原生会话；普通快照、导航历史及后台检查点采用相同校验。校验和用于发现内容损坏，不是签名或来源认证。

会话创建时将地图固定到 `data/maps/{id}/runtime-revisions/{sha256}.zmap`，原地图被替换后，已有会话仍使用其创建时的内容。恢复要求当前地图内容与快照匹配；不会静默用新版道路索引重放旧动作。版本文件目前保留，不自动回收。重放契约记录兼容语义，不保证任意编译器、平台或未来引擎版本的位级一致性。

旧版 1/2 快照仍可恢复，但返回 `integrity: legacy_unverified`；无法验证其原始内容或地图版本。格式 3 返回 `integrity: verified`。界面明确显示校验状态。

Agent 任务中的“恢复扫描”可启用网络改善通知（0 关闭）。收到 `route_improved` 后，自定义 `route(ctx)` 可重新比较路径或 `ctx.keep()`；引擎不会代替自定义代码换路。收益门槛与冷却属于原生自动车辆配置，自定义策略可在自己的逻辑中决定稳定性。
