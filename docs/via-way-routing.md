# Via-way 转向限制

OSM 的 `via-way` 表示限制跨越一条或多条道路，必须保留进入道路的历史。当前支持机动车静态 `no_*` / `only_*`：`from → via… → to`。例如禁止 `A → B → C` 时，从其他道路进入 B 后驶向 C 仍然合法；车辆从 B 中途新出发也不会继承 A 的限制。语义参考 [OSM Turn Restriction](https://wiki.openstreetmap.org/wiki/Turn_Restriction)。

## 提取与地图格式

`zeus-osm-turns` 接受一个 from、一个 to、1–16 个 via-way。提取器读取这些 way 的节点，按拓扑寻找唯一连接顺序，不依赖 relation 中 via 成员的排列；混合 via-node/via-way、缺失道路、歧义连接或无法确定顺序的关系会跳过并按原因计数。顺序搜索最多 10,000 次展开。既有 `restriction:motorcar` 和 `except=motorcar` 处理保持不变。

sidecar 保留原有 via-node 五列及罚时六列格式，增加：

```text
# from_source_id,entry_x,entry_y,to_source_id,type,ordered_via_way_ids
100,114.001,30.0,400,no_via,200;300
100,114.001,30.0,500,only_via,200;300
```

入口坐标使用源道路 CRS；第六列是按行驶顺序排列的源 way ID。导入器匹配切分后的 `way#partN` 道路，按有向拓扑展开为完整道路序列。单条关系最多 64 条展开序列、20,000 次搜索，每条序列最多 256 条有向道路；via 部分不重复经过同一节点。未解析到道路链会产生 `TURN_RESTRICTION_UNRESOLVED` 警告；超过展开预算产生 fatal 错误，不保存该关系的部分结果。闭环和歧义关系尚不完整支持，需检查导入 issues。

`.zmap` 现在写入版本 3，在既有禁转/罚时之外保存有序道路序列及 no/only 类型。新加载器兼容 v1/v2；旧地图没有序列规则，既有路由行为保持一致。旧版程序不能读取 v3 地图。新增规则需要重新编译原始道路和 sidecar，升级程序不会自动给旧地图添加规则。

## 历史状态与搜索

只读 MapRuntime 建立有界前缀自动机（最多 100,000 个状态）；导入阶段以序列道路总数不超过 99,999 作保守预算检查。它同时追踪当前道路历史匹配的多个规则前缀，检查重叠规则及后缀规则：

- `no` 仅禁止完成完整序列，未走完 via 前可以离开。
- `only` 从进入 from 后开始要求后续道路符合序列，不能在 via 中途提前离开。同一前缀的多个 only 规则允许各自下一条道路的并集；同时触发的不同前缀约束需全部满足。
- 目的地可以位于受约束道路中途，停车不算驶入下一条道路。转向罚时、封路和费用仍分别检查。

搜索状态包含当前有向道路与历史。非根前缀唯一确定末尾道路，因此状态数为道路数加前缀数减一，而不是两者相乘。Dijkstra 在此状态图上搜索；时间依赖 Dijkstra 保留 FIFO 分时速度模型和出发时刻计算。

A*、双向搜索、LPA*、D* Lite、ALT、CH 和 Yen 尚未针对这一状态图实现各自优化。含序列规则的地图上，这些入口明确返回 `effectiveAlgorithm=dijkstra` 和 `fallbackReason=via_way_history`；Yen 此时只返回一条合法最短路线。工作台显示回退原因。没有序列规则的地图继续使用原算法；不会在忽略限制的图上运行加速查询。

自定义算法获得相同的历史状态图。`ctx.neighbors(state)` 的 `state` 是不透明搜索状态，`edge` 才是物理道路 ID；多个状态可能对应同一条道路。代码应沿后继遍历状态，不能把道路 ID 当作状态 ID。已有模板无需修改。实验室仍限制最多 500,000 个状态和 2,000,000 个转换。

## 行驶、提交与恢复

仿真在出发时初始化历史，在真正驶入下一条道路时更新。移动起点规划、自动重规划、Agent 原生候选、自定义候选与精确路径验证使用同一历史；更新路线不清空它。非法候选会在提交时被拒绝，车辆驶入下一条道路时也会再次检查。

含序列规则的地图中，原生候选保存精确道路序列；最多 9999 条道路。快照仍使用格式 3 / `zeus-session-replay-v3`：恢复通过固定地图、时间步和已记录动作重放历史，不依赖旧进程的内存游标。新地图文件会改变地图哈希，原有地图绑定校验仍适用。

## 验证与边界

测试覆盖切分 via-way 导入、no/only 序列保存加载、OSM 成员顺序恢复与歧义拒绝、不同入口、移动起点、重叠规则、多个 only 的允许集合、分时速度及非法精确路径拒绝。另以完整路径切片枚举作为独立判定，生成 120 组路网和混合 no/only/封路/费用条件，对 10 个算法入口的可达性和最短费用逐一比较。

端到端脚本包含独立小型 via-way 地图：导入 → HTTP 十算法 → Python 自定义状态图 → 行驶中暂停 → 跨进程快照恢复 → 精确路线提交 → 到达。完整回归同时检查不含新规则的旧地图。

仍未支持 conditional restriction、完整车型 AccessMask、时间段例外、多 from/to 的 no_entry/no_exit、一般闭环关系和 via-way 加速索引；这些不计为本次完成。

2026-09-26，本地湖北 PBF 实测：bbox `113.7,29.9,115.1,31.4` 提取 109 条规则，其中 3 条 via-way。这 3 条关系涉及的源道路均不在现有武汉裁剪路网中，重新编译时明确报告未解析，生成地图的 `turn_sequences=0`、fatal=0；不把该数据集当作真实 via-way 通行案例。规则执行由上述可控路网与独立穷举验证。原有数据文件未修改。
