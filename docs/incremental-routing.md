# LPA* 与 D* Lite 增量路由

算法标识分别为 `lpa` 和 `dstar`，能力注册表版本均为算法自身的 `1`，声明支持动态权重和增量修复。可在 Agent 任务、候选比较、Benchmark 和普通路由选择中使用；普通路由请求不保留查询状态，界面标记为“单次搜索”。CLI 仿真可设置 `--algorithm lpa` 或 `--algorithm dstar`。

`lpa` 采用反向 LPA*，以进入路口的有向道路作为状态，保留 `g/rhs` 标签和不一致状态队列。启发式为 0，注册表的 `usesHeuristic` 因此为 false；这不是 D* Lite。算法依据见 [Koenig、Likhachev、Furcy 的 LPA* 论文与勘误](https://idm-lab.org/bib/abstracts/Koen04a.html)。

`dstar` 采用 D* Lite 的二元优先级 `(min(g,rhs)+h+km, min(g,rhs))`，随起点移动累积 `km`，弹出旧队列项时按新优先级延迟更新。依据 [Koenig、Likhachev 的 D* Lite 原始论文图 3](https://idm-lab.org/bib/abstracts/papers/aaai02b.pdf)，在同一有向边态模型上实现；与 LPA 共用 `IncrementalSearch` 的更新、转向检查和路径提取逻辑。切换算法会清空标签与队列，不能把另一算法的上下文计为复用。

D* Lite 的启发式针对部分道路和多起点做了保守处理：以第一个起点道路的终点为圆心，以覆盖全部起点终点所需的最大距离为半径，`h(s)=scale*max(0, distance(anchor,s)-radius)`。所有起点后继的启发值均为 0，因此虚拟起点连接也满足一致性；其余边态转换的坐标距离由实际基础边费用约束。`scale` 取所有非零端点距离道路的 `cost/distance` 最小值并留出浮点裕量，不假定存储道路长度等于投影距离；退化地图可退回零启发式。起点变化时 `km` 增量为 `scale*(圆心移动距离+半径变化绝对值)`，保证旧优先级仍是新优先级的下界，适用于 exact/twin 起点切换与向后移动。

## 状态变化与路径语义

- 同一目标下，封路、开放、费用上升/下降仅更新受影响状态并传播不一致；车辆沿路移动通过更新虚拟起点连接处理。
- 目标有向边、目标偏移、可用目标 twin 或算法改变时重建标签。地图运行时不同的上下文不能混用。
- 所有转向转换均按正向 `(from_edge, to_edge)` 验证禁转和罚时；反向搜索只改变计算方向。
- 精确起点已位于封闭道路上时可完成当前路段，但不能重新驶入该封闭道路。目标偏移和当前位置均保留双精度。
- 两种增量算法的 Agent 候选按完整精确路径提交、校验并记录到快照中，最多 9,999 条道路；执行不依赖提交时缓存是否存在。闭环、自环部分道路和相同道路直接到达使用一致的路径表示。

## 生命周期与指标

每个 Session Worker 最多保留 4 个 `(sessionId, vehicleId)` 查询上下文，采用最近使用顺序淘汰；关闭/重置会话时释放。仅在请求 LPA/D* Lite 时分配。原生仿真中含 LPA/D* Lite 自动车辆时，每个仿真运行最多保留一个上下文，不按车数分配；不同目的地或算法交替时会重新初始化。只有 Agent 车辆的仿真不额外保留引擎搜索标签。

持久化快照保存场景和已提交路径，不保存搜索标签。服务重启、上下文淘汰后第一次规划为冷启动，后续请求继续复用。Worker 的候选集合同时清理过期状态版本，并将当前版本的候选数量限制为 128。

Agent `/plan` 结果新增：

| 字段 | 含义 |
| --- | --- |
| `incrementalReused` | 本次使用了同一算法、同一目的地的已有标签 |
| `updatedEdges` | 与上次输入相比，关闭状态或费用因子发生变化的道路数量；首次输入与全开放、费用因子 1 比较 |
| `expandedNodes` | 本次实际处理的道路状态数量；不包含虚拟起点 |

相同请求再次查询无需扩展道路状态，但仍需校验输入、比较 overlay 和组装路径。当前 overlay 差异检测为 O(E)，每个上下文内存为 O(E)，搜索队列同一状态最多保留一项；因此“0 次扩展”不等于零耗时，也不保证任意场景都比 A* 快。Benchmark 可选择 `reactive` 策略和 `algorithm: "lpa"` 或 `"dstar"`；该策略维持原有仅对路线失效作出反应的规则，主动采用恢复路线可使用规则 Agent。

## 重放兼容性

LPA* 接入时同时修正了“驶出已关闭的当前道路”的精确路径校验，以及自环跨端点时保留两段部分道路的问题，重放契约升级为 `zeus-session-replay-v3`。此前格式 3、契约 v2 的快照会被拒绝，不会假定执行语义一致；旧格式 1/2 仍按既有未校验兼容路径读取。

新增 D* Lite 沿用上述 v3 契约；此次未改变其他算法的执行与回放语义，不额外升级快照格式或契约。

## 验证范围

路由测试包含 LPA*、D* Lite 各 240 次连续修改的 Dijkstra 对拍（含不可达再恢复、目标更换、当前位置变化、转向限制、费用升降），每轮重复查询断言复用且扩展数为 0；另有 600 组冷启动对拍，涵盖 twin、多源/多目标和动态 overlay。D* Lite 另含 80 次 exact/twin 起点切换及前后移动，验证启发式在网格上减少扩展、存储长度异常下仍可采纳。精确路径独立验证实际费用与道路合法性；原生车辆覆盖封路/恢复与换路冷却。

端到端脚本覆盖 HTTP 算法选择、初次/重复查询、封路修复、重新开放、精确路线提交、跨服务重启恢复、最终到达、四个上下文的缓存上限，车辆移动与算法切换，以及 Python Benchmark 的 LPA/D* Lite 策略。

LPA* 实测：临时路网首次/重复/封路修复分别扩展 4/0/2 个道路状态；武汉测试 OD 分别为 279/0/256。两者均完成道路恢复后的精确路径提交、服务重启和最终到达，Python reactive LPA Benchmark 也通过。未将这些扩展数当作大规模端到端加速结论。

D* Lite 实测：临时路网首次/重复/封路修复分别扩展 3/0/3 个道路状态；武汉同一 OD 为 145/0/184。两组均通过移动起点、算法切换、缓存淘汰、道路恢复后的精确提交、跨服务重启和最终到达；武汉 Python Benchmark 的 custom_code、reactive LPA、reactive D* Lite 三策略全部通过。端到端脚本改为异步等待 Python Benchmark，使主进程能持续读取服务日志，避免同步等待期间输出管道堵塞；保留原 120 秒超时。
